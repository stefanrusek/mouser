# Contract: Peer Wire Protocol (v1)

Producer and consumer: `mouser-core` on every desk computer (both sides are the same crate, but each message type is a seam between the sending role and the receiving role and gets `contract_` tests for both roles). Message types are defined once in `crates/mouser-proto` (Rust types, serde) and encoded with `postcard`; this document is normative for their meaning and the Rust types are generated by hand from it once and then frozen.

## Protocol version

- `PROTOCOL_VERSION: u16 = 1`. Sent in `Hello`. Peers with different major protocol versions are `Incompatible` (data-model ConnectionState) and each side raises an `incompatible_version` Problem naming both Mouser versions and which is older (Story 1 sc. 8).

## Discovery (LAN service advertisement)

- Service type `_mouser._udp.local.` (DNS-SD over mDNS).
- Instance name: computer display name.
- TXT keys: `v` (protocol version), `cid` (ComputerId, hex), `desk` (desk_id hex, or empty when unjoined), `dn` (desk name), `port` (QUIC port).
- Advertised addresses: only interfaces classified as physical LAN (Ethernet/Wi-Fi with a private or link-local unicast address); virtual/VPN/bridge interfaces are excluded (research R3).
- Manually added peers (Story 1 sc. 6) are dialled directly at `host:port` and then speak the same protocol.

## Transport

- QUIC (quinn), ALPN `mouser/1`. Each computer has one endpoint bound to `[::]:port` (dual stack) with fallback to `0.0.0.0:port`.
- TLS identity: self-signed certificate over the device key; peers verify that the certificate key hashes to the expected ComputerId (no CA). Desk membership is proven inside the connection by `DeskAuth` (below).
- Channels:
  - **Unreliable datagrams**: pointer motion (latest-wins, carries `seq`).
  - **Control stream** (bidirectional, reliable, ordered): everything else, length-prefixed postcard frames.
  - **Transfer streams** (one unidirectional stream per transfer item): file bytes.
- Keep-alive and idle timeout values are set from research R2 so path loss is detected and recovered within SC-008's 5 s.

## Motion datagram

`{ seq: u64, display_id_hash: u32, x: f32, y: f32 }` in the target display's logical coordinates. Receiver discards datagrams with `seq` lower than the last applied.

## Ordering and loss guarantees (Story 3 sc. 1, SC-002)

- `Key`, `Button`, `Scroll` travel on the reliable ordered control stream; QUIC retransmission plus connection migration means none are lost while the connection survives.
- If the connection is lost, the controller keeps its local pressed-state and on `Enter` after reconnection sends `ReleaseAll` first; keys typed during the outage go to the controller's own computer (control returned locally, Story 3 sc. 5), so no keystroke is silently dropped.
